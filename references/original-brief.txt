ROC = (x_t - x_t-1) / Δt

Evidence Strength

G. Raw data must never be deleted because it looks wrong.

J. Every displayed benchmark value must come from real evaluation artifacts.

No hardcoded “91% F1” or “98% confidence” placeholders in final production/demo screens.

5. EDGEGUARD — TINYML EDGE INTELLIGENCE
============================================================

Create a dedicated EdgeGuard subsystem.

The purpose of EdgeGuard is NOT to make the final authoritative distinction between genuine weather and sensor fault.

Its job is:

“Does this station’s current behaviour look suspicious compared with the patterns it has learned locally?”

The edge should classify only:

EDGE_NORMAL

8. PHYSICS CONSISTENCY ENGINE
============================================================

Physics must be a FIRST-CLASS layer.

Do not treat physics as a small optional feature.

The goal is not to claim that derived values are independent sensors.

The goal is to transform T/P/RH into physically meaningful atmospheric representations and determine whether observed behaviour is internally and contextually coherent.

Create five physics sub-engines:

1. Thermo-Hygrometric Engine
2. Pressure Physics Engine
3. Hydrostatic/Elevation Engine
4. Atmospheric State Engine
5. Physics Residual Engine

============================================================
8.1 Saturation vapour pressure
============================================================

From temperature:

e_s(T) = 6.112 * exp((17.67*T)/(T+243.5))

Use appropriate units.

============================================================
8.2 Actual vapour pressure
============================================================

e = RH/100 * e_s(T)

============================================================
8.3 Dew point
============================================================

Calculate dew point using a Magnus-type formulation.

Also calculate:

dew point depression:

DPD = T - Td

Do not describe calculated dew point as an independent sensor.

============================================================
8.4 Vapour pressure deficit
============================================================

VPD = e_s - e

============================================================
8.5 Mixing ratio
============================================================

w = 0.622 * e / (P - e)

============================================================
8.6 Specific humidity
============================================================

q = 0.622e / (P - 0.378e)

============================================================
8.7 Virtual temperature
============================================================

T_v = T_K * (1 + 0.61q)

============================================================
8.8 Air density
============================================================

rho = P / (R_d * T_v)

Use consistent SI units.

============================================================
8.9 Potential temperature
============================================================

theta =
T_K * (P0/P)^(R_d/c_p)

with an appropriate standard reference pressure.

============================================================
8.10 Pressure tendency
============================================================

Compute:

dP/dt

and optionally:

d²P/dt²

Pressure tendency can be more useful than absolute pressure alone for weather propagation.

============================================================
8.11 Elevation-aware pressure comparison
============================================================

Never compare raw pressure blindly across stations with significantly different elevation.

Use:

station elevation
temperature context
pressure reference metadata

Determine whether pressure is:

station pressure
mean sea level pressure
another reference

Normalize appropriately before spatial comparison.

============================================================
8.12 Hard physics vs soft physics
============================================================

Hard constraints may include:

invalid RH representation
impossible data encoding
NaN
corrupted pressure values

Soft constraints should produce evidence rather than automatic rejection.

Example:

Temperature jumps dramatically,
RH remains unchanged,
implied moisture changes strongly,
pressure unchanged,
nearby stations show no similar behaviour.

Output:

high physics inconsistency evidence

not:

“physically impossible”

unless it truly violates a hard constraint.

============================================================
74. CORE PITCH
============================================================

The architecture should support the following concise explanation:

“SkyGuard uses intelligence at two levels. At the weather station, a quantized TinyML autoencoder together with lightweight physics and statistical checks continuously screens sensor behaviour, even when network connectivity is lost. At the central platform, each observation is evaluated against station history, atmospheric physics, temporal forecasting, neighbouring AWS stations, Numerical Weather Prediction and a Virtual Weather Twin. These independent evidence sources are fused using a calibrated decision model with explicit uncertainty handling. This allows SkyGuard to distinguish genuine extreme weather from sensor and communication failures instead of simply flagging unusual values. Raw measurements remain immutable, corrections are only proposed when multiple independent estimators agree, and every decision is explainable and auditable.”
